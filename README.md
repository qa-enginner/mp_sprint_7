# Микросервисная система аутентификации и авторизации

## Обзор проекта

Проект представляет собой микросервисную систему аутентификации и авторизации, разработанную в рамках второго спринта. Система включает в себя несколько взаимосвязанных сервисов, обеспечивающих безопасную регистрацию, аутентификацию пользователей, управление правами доступа и интеграцию с другими сервисами платформы.

## Архитектура

Система состоит из следующих основных компонентов:

1. **Auth Service** - основной сервис аутентификации и авторизации
2. **Content Service** - сервис выдачи контента (фильмы, жанры, персоны)
3. **Admin Panel** - административная панель для управления пользователями и контентом
4. **ETL Service** - сервис для переноса данных из PostgreSQL в Elasticsearch
5. **Infrastructure** - базы данных (PostgreSQL, Redis), мониторинг (Jaeger), обратный прокси (Nginx)

## Ключевые достижения спринта

### 1. Интеграция Auth-сервиса с сервисом выдачи контента и административной панелью

Реализована полноценная интеграция между сервисами:
- **Auth Service ↔ Content Service**: Content Service проверяет JWT-токены, выданные Auth Service, для авторизации запросов к защищенным эндпоинтам
- **Auth Service ↔ Admin Panel**: Административная панель использует единую систему аутентификации для управления пользователями и ролями
- **Единая система ролей и разрешений**: Реализована согласованная модель прав доступа across всех сервисов
- **CORS настройки**: Настроены корректные CORS политики для безопасного межсервисного взаимодействия

### 2. Изящная деградация Auth-сервиса

Реализованы механизмы graceful degradation для обеспечения отказоустойчивости:
- **Кэширование токенов в Redis**: При временной недоступности PostgreSQL система продолжает работать с кэшированными данными
- **Резервные механизмы аутентификации**: Поддержка fallback-стратегий при частичных сбоях
- **Health-check эндпоинты**: Мониторинг состояния всех зависимостей сервиса
- **Автоматическое восстановление**: Система автоматически восстанавливает работу после устранения сбоев

### 3. Трассировка и подключение к Jaeger

Внедрена распределенная трассировка для мониторинга и отладки:
- **Интеграция OpenTelemetry**: Все сервисы инструментированы для сбора телеметрии
- **Jaeger как бэкенд**: Настроен сбор и визуализация трейсов в Jaeger
- **Tracing Middleware**: Реализовано промежуточное ПО для автоматической генерации трейсов
- **Корреляция запросов**: Уникальные идентификаторы запросов (request_id) для отслеживания цепочек вызовов
- **Метрики производительности**: Сбор данных о времени ответа, ошибках и загрузке сервисов

### 4. Механизм ограничения количества запросов к серверу

Реализована система rate limiting для защиты от злоупотреблений:
- **Redis-based rate limiting**: Использование Redis для хранения счетчиков запросов
- **Гибкие политики ограничений**: Настройка лимитов по IP, пользователям, эндпоинтам
- **RateLimitMiddleware**: Промежуточное ПО для проверки и ограничения запросов
- **HTTP 429 Too Many Requests**: Корректные ответы при превышении лимитов

### 5. Управление миграциями базы данных с Alembic

Внедрена система миграций базы данных для управления изменениями схемы:
- **Alembic для миграций**: Замена `Base.metadata.create_all` на полноценную систему версионирования схемы
- **Автоматическое применение миграций**: Миграции применяются автоматически при старте приложения через entrypoint скрипт
- **Поддержка asyncpg**: Конфигурация Alembic для работы с асинхронным драйвером PostgreSQL
- **Первая миграция**: Создана initial миграция на основе существующих моделей (users, refresh_tokens, login_history, social_accounts)
- **Откатываемые изменения**: Возможность отката миграций при необходимости
- **Интеграция с Docker**: Обновлен Dockerfile для копирования конфигурации Alembic и entrypoint скрипта

#### Команды для работы с миграциями:
```bash
# Создание новой миграции (после изменения моделей)
cd services/auth-service
alembic revision --autogenerate -m "Описание изменений"

# Применение миграций
alembic upgrade head

# Откат последней миграции
alembic downgrade -1

# Просмотр истории миграций
alembic history

# Проверка текущей ревизии
alembic current
```
- **Конфигурируемые квоты**: Возможность настройки лимитов через конфигурационные файлы

### 5. Упрощенная регистрация и аутентификация через Яндекс

Добавлена поддержка OAuth 2.0 для социальной аутентификации:
- **Яндекс OAuth интеграция**: Пользователи могут входить через аккаунт Яндекс
- **Единый вход (SSO)**: Интеграция с существующей системой аутентификации
- **Автоматическая регистрация**: Создание учетных записей при первом входе через OAuth
- **Слияние аккаунтов**: Возможность привязки социальных аккаунтов к существующим учетным записям
- **OAuth Factory Pattern**: Гибкая архитектура для добавления новых провайдеров

## Технологический стек

### Backend
- **Python 3.11+** - основной язык разработки
- **FastAPI** - фреймворк для Auth Service и Content Service
- **Django** - фреймворк для Admin Panel
- **SQLAlchemy** - ORM для работы с PostgreSQL
- **Redis** - кэширование и rate limiting
- **Elasticsearch** - полнотекстовый поиск для Content Service
- **PostgreSQL** - основная реляционная БД

### Инфраструктура
- **Docker & Docker Compose** - контейнеризация и оркестрация
- **Nginx** - обратный прокси и балансировка нагрузки
- **Jaeger** - распределенная трассировка
- **OpenTelemetry** - сбор телеметрии
- **JWT** - JSON Web Tokens для аутентификации

### Безопасность
- **bcrypt** - хеширование паролей
- **JWT с RSA** - асимметричное шифрование токенов
- **CORS middleware** - защита от межсайтовых запросов
- **Rate limiting** - защита от DDoS и brute force
- **Environment variables** - безопасное хранение секретов

## Быстрый старт

### Запуск с помощью Docker Compose

1. **Клонируйте репозиторий**:
   ```bash
   git clone https://github.com/Practicum-MP/mp_sprint_7
   ```

2. **Создайте файл .env на основе .env.example**:
   ```bash
   cp .env.example .env
   ```
   При необходимости отредактируйте переменные окружения.

3. **Запустите сервисы**:
   ```bash
   docker-compose up -d --build
   ```

4. **Инициализация баз данных** (если требуется):
   ```bash
   chmod +x init-scripts/01-create-databases.sh
   chmod +x init-scripts/02-load-dump.sh
   ./init-scripts/01-create-databases.sh
   ./init-scripts/02-load-dump.sh
   ```
